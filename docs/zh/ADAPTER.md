# 共享适配器 — 原理与训练配方（不发权重）

[English](../en/ADAPTER.md) | **中文**

我们**不再分发训练好的适配器权重**。本文给出原理与配方，让你能在自己的底座/领域上训练。
（许可说明见下：分发其实是被允许的——底座是 Apache-2.0——但发方法而非工件，能让本仓更干净、领域无关。）

## 它是什么
一个小型、**共享、客户无关**的残差读写接口，架在**冻结**底座 LM 之上。
- 每个注入层 `li` 两个矩阵 `A_K[li]`、`A_V[li]`，各为 `head_dim × head_dim`。
- head_dim=256、4 个注入层时：`4 × 2 × 256 × 256 = 524,288` 参数（约 2MB）——约为 0.8B 底座的 0.06%。
- 注入时作用：`K' = K + s·(K @ A_K)`、`V' = V + s·(V @ A_V)`（s=injection_scale，默认 1）。
- **零初始化**（`torch.zeros`），故第 0 步注入即原始事实 K/V；训练学的是残差。

## 为什么需要它
冻结模型只"读得懂"自己的 K/V 格式。把原始事实 K/V 直接拼到注意力前部，模型扫一眼但不用。
适配器把注入 K/V 变换成模型会注意、会据以行动的形式。
实测（W62）：**无适配器注入利用率约 17.5%；有适配器约 95%。** 它是"记忆在场"到"记忆被用"的桥。

## 训练原理
只训适配器；底座冻结（所有底座参数 `requires_grad_(False)`）。
1. 把事实的值 span 编码成逐层 K/V 行（冻结前向）——即记忆。
2. 构造一个答案为该事实值的查询；把事实 K/V（经适配器）注入注意力。
3. 计算模型在**答案 token**上的 logits；loss = `cross_entropy(logits, answer_ids)`。
4. **只回传到 `A_K`/`A_V`**；优化器步进。（适配器运算用 float32 保梯度稳定。）

目标：让注入的记忆*驱动模型吐出记住的值*。适配器学的是读取接口，不是新知识——知识存在外部记忆行里。

## 配方（参考超参）
- 底座：冻结 Qwen3.5-0.8B / 4B（Apache-2.0）；注入层如 (11,15,19,23)，ret_layer/ret_head 按模型定。
- 渲染：**自然句**（与推理时用的渲染一致——渲染错配代价约 25–35 点，W72/W109）。
- 数据：事实语料（如 DuIE/CMeIE，或你的领域事实），每语料约 200 实体，值长 ≤24 token。
- 优化器：lr 1e-3，约 3000 步，零初始化（或从模板训的适配器热启动）。
- 可训练：524,288 参数；其余全冻结。
